## 1. ブランチ全体像

```
gitea-private  ─── docs / openspec / .claude / .devcontainer / .gitea
                   （GitHub へは同期しない）

main           ─── リリース済み安定版（タグ打ちコミットのみ）
 │
 ├─ release/v* ─── リリース準備（main から分岐 → main へマージ）
 │
 └─ hotfix/v*  ─── 本番緊急修正（main から分岐 → main へマージ）

develop        ─── 開発統合ブランチ（次リリースの最新）
 │             ← release/* / hotfix/* のマージバック先
 ├─ feature/*  ─── 機能追加・バグ修正
 └─ chore/*    ─── 設定・依存関係・ビルドのみの変更
```

---

## 2. ブランチ一覧

| ブランチ | 命名規則 | 分岐元 | マージ先 | 役割 |
|---------|---------|-------|---------|------|
| `main` | 固定 | — | — | リリース済み安定版。タグが打たれたコミットのみ存在する |
| `develop` | 固定 | — | — | 開発統合。次リリースの最新状態を常に反映する |
| `feature/*` | `feature/{openspecの改修タイトル}` | `develop` | `develop` | 機能追加・バグ修正。openspec `changes/` のディレクトリ名と一致させる |
| `chore/*` | `chore/{内容}` | `develop` | `develop` | コード変更を伴わない設定・依存関係の更新 |
| `release/*` | `release/v{version}` | `main` | `main` + `develop` | リリース準備。バージョン番号・CHANGELOG の確定のみ行う |
| `hotfix/*` | `hotfix/v{version}` | `main` | `main` + `develop` | 本番の緊急修正 |
| `gitea-private` | 固定 | — | — | 内部ドキュメント専用。GitHub へは同期しない |

---

## 3. リモートとの対応

| ブランチ | Gitea | GitHub | 備考 |
|---------|-------|--------|------|
| `main` | ✅ push | ✅ 自動同期 | Gitea Actions が sync |
| `develop` | ✅ push | ✅ 自動同期 | Gitea Actions が sync |
| `feature/*` / `chore/*` | ✅ push | ❌ 同期しない | PR マージ後に削除 |
| `release/*` | ✅ push | ❌ 同期しない | マージ後に削除 |
| `hotfix/*` | ✅ push | ❌ 同期しない | マージ後に削除 |
| `gitea-private` | ✅ push | ❌ 同期しない | コード変更を含めない |

## 4. gitea-private ブランチの運用

`docs/` `openspec/` `.claude/` `.devcontainer/` `.gitea/` を管理する専用ブランチ。  
`main` / `develop` の `.gitignore` に登録されているため、コードブランチには影響しない。

### 内部ドキュメントを更新するとき

```bash
git checkout gitea-private

git add docs/ openspec/ .claude/ .devcontainer/ .gitea/
git commit -m "docs: ..."
git push gitea gitea-private

git checkout develop   # 作業ブランチに戻る
```

### 作業ブランチで内部ドキュメントを参照したいとき

```bash
./scripts/pull-private.sh
# gitea-private の内部ディレクトリを作業ディレクトリに展開する（アンステージ状態）
```

## 5. 命名規則

### ブランチ名

| 種別 | 形式 | 分岐元 | 備考 |
|------|------|-------|------|
| 機能追加・バグ修正 | `feature/{openspecの改修タイトル}` | `develop` | openspec の `changes/` 配下のディレクトリ名と必ず一致させること |
| 設定・ビルド変更 | `chore/{内容}` | `develop` | |
| リリース準備 | `release/v{MAJOR}.{MINOR}.{PATCH}` | `main` | |
| 緊急修正 | `hotfix/v{MAJOR}.{MINOR}.{PATCH}` | `main` | |

### コミットメッセージ（Conventional Commits）

| プレフィックス | 用途 |
|-------------|------|
| `feat:` | 新機能 |
| `fix:` | バグ修正 |
| `chore:` | ビルド・設定・依存関係・バージョン変更 |
| `docs:` | ドキュメントのみの変更 |
| `refactor:` | 機能変更を伴わないリファクタリング |
| `test:` | テストの追加・修正 |

## 6. 開発フロー

### 6.1 通常の機能開発

```
1. develop から feature ブランチを切る
   git checkout -b feature/xxx develop

2. 実装・コミット（Gitea へ push）

3. develop へ PR を作成・マージ（--no-ff）

※ feature ブランチはマージ後も削除しない（履歴として残す）
```

### 6.2 リリース手順

> **ルール**: 1つの release ブランチに含まれる機能は原則1つとする。

```
1. main から release ブランチを切る
   git checkout -b release/v1.5.0 main

2. feature ブランチを release へマージする
   git merge --no-ff feature/xxx

3. Cargo.toml のバージョンを更新
4. CHANGELOG.md の [Unreleased] を [1.5.0] - YYYY-MM-DD に書き換え
5. コミット: "chore: release v1.5.0"

6. 動作確認（バグ修正のみ可。新機能追加は不可）

7. main へマージ
   git checkout main
   git merge --no-ff release/v1.5.0

8. タグを打つ（GitHub Actions がトリガーされる）
   git tag v1.5.0
   git push gitea main --tags

9. develop へマージバック
   git checkout develop
   git merge --no-ff release/v1.5.0

10. release ブランチを削除
    git branch -d release/v1.5.0

※ feature ブランチは削除しない（履歴として残す）
```

### 6.3 緊急修正（hotfix）

```
1. main から hotfix ブランチを切る
   git checkout -b hotfix/v1.4.2 main

2. 修正・コミット

3. Cargo.toml のバージョンを更新
4. CHANGELOG.md を更新
5. コミット: "chore: release v1.4.2"

6. main へマージ
   git checkout main
   git merge --no-ff hotfix/v1.4.2

7. タグを打つ
   git tag v1.4.2
   git push gitea main --tags

8. develop へマージバック
   git checkout develop
   git merge --no-ff hotfix/v1.4.2

9. hotfix ブランチを削除
   git branch -d hotfix/v1.4.2
```

---

## 7. ルール・禁止事項

| ルール | 内容 |
|--------|------|
| main への直接 push 禁止 | 必ず release/* または hotfix/* 経由でマージする |
| develop への直接 push 禁止 | 必ず feature/* または chore/* 経由でマージする（緊急を除く） |
| --no-ff を使う | マージコミットを残してブランチ履歴を明確にする |
| docs を feature に混ぜない | ドキュメント変更は `gitea-private` に直接コミットする |
| タグは main のみ | バージョンタグは必ず main ブランチのマージコミットに打つ |
| feature のリリースは release/* 経由 | feature を直接 main へマージしない。main から release/* を切り、そこへ feature をマージしてからリリースフローを行う |
| feature ブランチは削除しない | マージ後も履歴として残す。削除するのは release/* のみ |

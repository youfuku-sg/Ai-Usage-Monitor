## 1. プロジェクト概要

### 1.1 背景

AI開発ツール（Claude Code 等）の利用が日常的になる中、使用量制限・サービス状態・ローカルLLMの稼働状況など、複数の情報を別々に確認する手間が生じている。

また、[ClawdMeter](https://www.reddit.com/r/ClaudeCode/comments/1takxpl/) に代表されるように、Claude Code の使用量制限をリアルタイムで把握したいニーズが存在する。

### 1.2 目的

AI開発環境に関する複数の状態情報を収集・集約し、バックグラウンドで常駐動作するハブシステムを構築する。これにより：

- AI開発ツールの使用状況をリアルタイムで把握できる
- 使用量が閾値を下回った際にシステム通知（Windows トースト通知）でアラームを受け取れる
- 単一のAPIエンドポイントから全情報を取得でき、外部デバイス（ESP32等）から状態を参照できる

### 1.3 システム名称と位置付け

```
[ Claude Code / Codex / ... ]
              ↓ データ収集
        【 AiPulseHub 】  ← 本システム（バックグラウンド常駐）
         ↓         ↓              ↓
  トースト通知  タスクトレイ      API配信
  （閾値アラーム） （ウィジェット・右クリックメニュー） [ AiPulseDesk / ESP32等 ]
```

AiPulseHub は AI環境全体の「鼓動（Pulse）」を収集し、閾値到達時に通知を送りながら外部端末へデータを届ける中核コンポーネントである。

## 3. 監視・収集対象

初期バージョンは **Claude Code のみ**を対象とする。

| 対象 | 取得情報 | 取得方法 |
|------|---------|---------|
| Claude Code | 5時間ウィンドウ内の使用率・リセット時刻・制限状態 | OAuth API（優先）／JSONL ローカルパース（フォールバック） |

> **7日ウィンドウについて**: 取得対象から除外する。ウィジェット・API・通知はすべて5時間ウィンドウの情報のみを使用する。

### データ取得方式

**プライマリ: OAuth API**

ローカルの認証情報ファイル（`%USERPROFILE%\.claude\.credentials.json`）に保存された OAuth アクセストークンを使用し、Anthropic の使用量 API からデータを取得する。Windows 上の認証情報が存在しない場合、WSL ディストリビューションの認証情報も順に探索する。

**フォールバック: ローカル JSONL パース**

OAuth API が利用できない場合（認証情報なし・ネットワーク不達等）は、`%USERPROFILE%\.claude\projects\**\*.jsonl` をローカルでパースしてデータを算出する。

Claude Code のインストール有無は起動時に認証情報ファイルまたは `%USERPROFILE%\.claude\projects\` ディレクトリの存在で判定し、存在しない場合は表示対象から除外する（エラー扱いにしない）。

> **将来拡張候補**（スコープ外）: Codex、システム情報、Docker、LM Studio、ローカルLLM

## 4. 機能要求

### 4.1 データ収集機能

**REQ-COL-001**: 起動時に Claude Code の認証情報またはプロジェクトディレクトリの存在を確認し、インストール有無を判定できること

**REQ-COL-002**: OAuth アクセストークンを使用し、Anthropic の使用量 API から5時間ウィンドウの使用率・リセット時刻を取得できること

**REQ-COL-003**: トークンが期限切れの場合、Claude CLI を呼び出してリフレッシュを試み、更新後のトークンで再取得できること

**REQ-COL-004**: Windows の認証情報が利用できない場合、WSL ディストリビューション上の認証情報（`~/.claude/.credentials.json`）を順に探索して利用できること

**REQ-COL-005**: OAuth API が利用できない場合、`%USERPROFILE%\.claude\projects\**\*.jsonl` をスキャンしてフォールバック計算できること。JSONL パース時は `message.id` による重複排除・過去10時間のエントリから5時間ウィンドウを算出すること

**REQ-COL-006**: Claude Code が未インストールの場合はエラーとせず、表示対象から除外すること

**REQ-COL-007**: 取得した情報に最終更新時刻のタイムスタンプを付与できること

**REQ-COL-008**: 収集処理を一定間隔（デフォルト: 30秒）で定期実行できること

### 4.2 API提供機能

**REQ-API-001**: 収集した全情報をまとめて返すエンドポイント（`GET /status`）を提供できること

**REQ-API-002**: 監視対象ごとに個別のエンドポイント（例: `GET /status/claude`）を提供できること

**REQ-API-003**: サービス死活確認エンドポイント（`GET /health`）を提供できること

**REQ-API-004**: レスポンス形式はJSON とすること

**REQ-API-005**: ローカルネットワーク内の他デバイスからAPIにアクセスできること

### 4.3 通知機能

**REQ-NOTIFY-001**: 監視対象サービスの使用率が以下の閾値に達した時点で、Windows システム通知（トースト通知）を送出できること

| 閾値（使用率） | 通知タイミング |
|:---:|---|
| 80% | 使用率が80%に達した時点 |
| 90% | 使用率が90%に達した時点 |
| 95% | 使用率が95%に達した時点 |
| 98% | 使用率が98%に達した時点 |

**REQ-NOTIFY-002**: 同一閾値での通知は、現在の5時間ウィンドウ内で1回のみ送出すること（ウィンドウリセット後はリセット）

**REQ-NOTIFY-003**: 通知には以下の情報を含めること

- 対象サービス名（例: 「Claude Code」）
- 現在の使用率（例: 「使用率: 80%」）
- 制限リセットの予定時刻（例: 「リセット予定: 15:30」）

**REQ-NOTIFY-004**: 通知閾値は設定ファイルで変更できること

### 4.4 タスクトレイ機能

**REQ-TRAY-001**: Windows のタスクトレイ（通知領域）にアイコンを常駐できること

**REQ-TRAY-002**: タスクトレイアイコンにカーソルを合わせると、現在の使用率とリセット時刻（HH:MM形式）をツールチップで確認できること

**REQ-TRAY-003**: タスクトレイアイコンを右クリックするとコンテキストメニューが表示できること

**REQ-TRAY-004**: 右クリックメニューから現在の状態（残容量・リセット予定時刻）を確認できること

**REQ-TRAY-005**: 右クリックメニューからアプリケーションを終了できること

### 4.5 タスクバーウィジェット機能

**REQ-WIDGET-001**: タスクバーに埋め込まれるウィジェットを表示できること

**REQ-WIDGET-002**: ウィジェットは監視対象サービスを1行1サービスで縦に並べて表示すること

- 1行目: Claude Code の使用率・リセット時刻（HH:MM形式。例: `40% · 15:30`）
- 2行目以降: 将来のサービス追加に備えて拡張できること（例: Codex）

**REQ-WIDGET-003**: タスクトレイアイコンを左クリックすることでウィジェットの表示・非表示を切り替えられること

**REQ-WIDGET-004**: Claude Code が未インストールの場合、該当行は非表示またはグレーアウト表示とすること

### 4.6 自動アップデート機能

**REQ-UPDATE-001**: 起動後および一定間隔（デフォルト: 1時間）ごとに新バージョンの有無を確認できること

**REQ-UPDATE-002**: アップデート確認先は Gitea（ローカル）を優先し、到達できない場合は GitHub へ自動フォールバックできること

**REQ-UPDATE-003**: 新バージョン検出時、バックグラウンドでダウンロードし、完了後にトースト通知でユーザーに通知できること

| 通知項目 | 内容 |
|---------|------|
| タイトル | `AiPulseHub アップデートあり` |
| 本文 | 現在バージョン → 新バージョン、クリックで適用する旨 |

**REQ-UPDATE-004**: ユーザーが通知をクリックすることでインストーラを実行しアプリを再起動できること

**REQ-UPDATE-005**: 自動アップデート機能の有効・無効を設定ファイルで切り替えられること

**REQ-UPDATE-006**: アップデートチェックに失敗した場合（ネットワーク不可・エンドポイント不達）はエラーとせず、次回チェックまで待機すること

**REQ-UPDATE-007**: ダウンロードしたファイルの署名を検証し、署名が不正な場合はアップデートを中止できること

## 5. 非機能要求

### 5.1 動作環境

**REQ-ENV-001**: Windows 11 上でローカル動作すること（クラウドサービス不要）

**REQ-ENV-002**: 常駐プロセスとしてバックグラウンドで動作できること

**REQ-ENV-003**: WSL 環境の Claude Code の認証情報も読み取れること

### 5.2 性能

**REQ-PERF-001**: APIレスポンスはキャッシュされた最新データを返し、500ms以内に応答できること

**REQ-PERF-002**: 収集処理が遅延・失敗してもAPIの応答性に影響しないこと

### 5.3 保守性

**REQ-MAINT-001**: 収集間隔・通知閾値などの動作設定を設定ファイルで変更できること

**REQ-MAINT-002**: 各収集モジュールは独立して実装・テストできること

**REQ-MAINT-003**: 将来のサービス追加（Codex等）に対してウィジェット・API・通知を最小限の変更で拡張できること

## 7. 用語定義

| 用語 | 定義 |
|------|------|
| AiPulseHub | 本システム。AI開発環境の状態収集・API提供を行うローカルハブ |
| AiPulseDesk | AiPulseHub のAPIを受信して状態表示を行う外部端末の総称（ESP32等） |
| Pulse | AI開発環境全体の状態情報。AiPulseHub が収集・配信する情報の比喩的表現 |
| 使用量制限 | Claude Code のトークン・リクエスト数に対する制限。一定時間ごとにリセット |
| 残容量 | `(上限 - 使用量) / 上限 × 100`（%）で表した残りの使用可能量 |
| 5時間ウィンドウ | Claude Code のレート制限の計算基準となる直近5時間の区間 |
| ポーリング | 一定間隔でAPIやサービスの状態を問い合わせる方式 |
| ウィジェット | タスクバーに埋め込まれる使用量表示パネル |
